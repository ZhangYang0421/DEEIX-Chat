# 上游更新经验（简明版）

这份记录只保留本次更新得到的经验，方便以后更快、更稳地更新，不要求使用者理解项目内部细节。

## 更新时遵循的原则

1. 先确认上游这次实际改了什么，只检查受影响的部分，不从头通读整个项目。
2. 优先检查本地定制功能：音频转写、OCR、图片输入限制、Transcript 编辑、Embedding/RAG、文件上传和存储。
3. 以新的上游代码结构为基础，把本地功能逐项接回去；不使用旧代码整块覆盖新代码。
4. 遇到问题按顺序处理：先确认问题能复现，再找原因，做最小修改，最后重新验证；不顺手改无关代码。
5. 验证顺序固定为：本地编译和测试 → 项目质量检查 → 镜像构建 → 生产更新 → 健康检查。
6. 更新生产时只替换应用程序，保留数据库和文件存储；不删除数据卷，不使用破坏性操作。
7. 如果上游没有影响本地功能，就不扩大检查范围，也不做无关改动。

## 完成后只需要说明这些

- 是否更新成功；
- 本地功能是否保留；
- 测试和质量检查是否通过；
- 是否发布镜像、更新生产；
- 是否还有未解决的问题。

说明使用简单中文，技术细节只在确实影响结果时出现。

## 以后可以直接这样提出请求

> 把上游最新版本同步过来，保留现在已有的本地功能，按之前总结的经验处理，完成后用简单中文告诉我结果。
